## P1 —— 30–60 分鐘真實會議 E2E ★最高

**依據**：`BLUEPRINT_2026-07-29.md` §4.1 的第一項，7/29 列入計畫至今未執行。
`GOAL_PHASE_2.md` 序 7 同樣列為「真實會議手測」。

**為什麼第一**：這是把整個系統的可靠度宣稱從「mock 背書」升級為「真實背書」的
唯一動作，資訊量最大。做完之前，任何新功能都是蓋在未驗證的地基上。

**成本**：寄生在已排定的會議上，零額外時間（`GOAL_PHASE_2.md:114` 原則）。

**一次收掉五項卡住的工作**：

| 併收項                                | 現況                                       |
| ------------------------------------- | ------------------------------------------ |
| D2 Gemini 32ms／100ms chunk screening | `PHASE_2_RUN.md` 序 7，deferred 待真人講話 |
| `meeting` 聲學設定驗證                | `TODO.md:146`，2026-06-08 起掛著           |
| 1 小時 soak ＋ bounded heap           | `BLUEPRINT` §4.1                           |
| C1 延遲文案所需的實測數字             | 目前 UI 刻意不寫任何延遲數字               |
| WebSocket 傳輸在公司網路的實戰        | D13 已做單次 live 驗證，未經真實會議       |

**完成條件**：一份會後紀錄，含 `window.__latency` 匯出、field-test 紀錄、
斷線／切換是否發生、heap 趨勢。**任何一項沒觀察到就寫「未觀察」，不補敘事。**

**誰動手**：使用者開會；會前我出一張 30 秒可讀完的檢查卡，會後我判讀。

## P2 —— Summary 管線（draft／refined／stable）★次高

**依據**：`CLAUDE.md` 產品目標第 5 條與實作順序第 11 項；
`BLUEPRINT_2026-07-29.md:109` 列為 deferred。

**為什麼**：這是**唯一整包未建的核心產品目標**。目前系統能即時給字幕，
但會議結束後不留下任何有用的東西。對「開會」而言那是產品的另一半。

**最小垂直切片**（不是完整功能，是能用的第一刀）：

1. 只吃 `captionStore` 的 finalized segments，**絕不吃 partial delta**（CLAUDE.md 硬規則）。
2. bounded 有序 dispatcher，壓力下丟舊的，**絕不阻塞字幕路徑**——
   複用 `services/offline/app/pipeline/translation_dispatcher.py` 的既有模式。
3. 三狀態 `draft` / `refined` / `stable`，UI 明確標示，不得混為一談。
4. 線上走 `services/online` 的伺服器端端點（key 不進瀏覽器）；
   離線模式**誠實顯示不支援**，不做假摘要。
5. 可收合側欄，不得搶字幕版面（目前 UI **完全沒有**任何摘要元件）。
6. 失敗隔離測試：摘要炸掉，字幕、翻譯、音訊、切換全部不受影響。

**成本**：估 3–5 人日（含測試與失敗隔離）。**誰動手**：我。

**風險**：這是新的外部呼叫路徑，必須先確認它不會偷走字幕路徑的主執行緒時間——
沿用 `caption-longtask.spec.ts` 的量測手法驗證。

## P3 —— 首字幕延遲實驗（3.1s → 2.0–2.2s）

**依據**：[`GEMINI_V1BETA_LATENCY_COST_DIAGNOSIS_2026-08-28.md`](GEMINI_V1BETA_LATENCY_COST_DIAGNOSIS_2026-08-28.md)
§7／§10 的實測與推導。

**為什麼**：延遲是使用者在會議中最有感的單一屬性。現行 Live Translate 第一個
有意義譯文中位數 **3.113s**；Transcribe Live ＋ Flash-Lite 推導為 **1.9–2.2s**，
改善 30–38%。

**紀律**：只做 feature flag 後的 prototype，**不動主路徑**。診斷報告 §Phase C
已訂門檻（第一譯文 P50 ≤2.2s／P95 ≤3.0s、final P50 ≤1.0s、品質不得低於基線、
成本 ≤US$0.014/min），未全數通過**不得更換預設**。

**成本**：prototype 2–3 人日；production 化 7–12 人日。**誰動手**：我，需真配額做基準。

## P4 —— Offline 真引擎實跑

**為什麼**：隱私場景的一等公民（CLAUDE.md「Online 與 Offline 都是一等公民」），
自動化 81 條今天全綠，但真引擎／真音訊路徑最後驗證在 2026-05～06。

**價值是條件性的**：只有在確實會用到「不能上雲」的會議時才緊急。

**成本**：5 分鐘（`pnpm dev:full` 起服務，我判讀 log）。**誰動手**：使用者起服務。
